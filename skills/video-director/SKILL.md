# Video director

Resolve project paths from the repository root, two levels above this skill folder.

Read `../../start.md` for intake and `../../brief.json` for current sources.
Read `../../design-lead.md` before concept selection, a worker brief, or design critique.
Read `../../audio-to-visual-director.md` for scene craft and `../../workflow.md` for production order.

Honor the user's scope. A design-only assignment with a separate worker ends with a concrete design package and next production tasks. A full-production assignment continues through implementation and export. One agent may perform both roles sequentially; these instructions do not require additional agents.

Define the audience's starting point, primary outcome, message, evidence, and emotional progression. Choose a creative concept and visual language that serve this request. The user should not need to select tools or supply design expertise. Inspect current references; do not inherit the previous video's story, palette, or layout. Keyword categories and shared archetypes cannot choose the concept.

Use `../../templates/direction.md` to write `work/current/direction.md`: strategy, chosen concept, research/reference findings, directed meaning beats, asset choices, motion/transition language, and the worker brief. Keep timed operations in the existing storyboard format. Produce actual style frames, an animatic, and a representative sample within the authorized production scope; distinguish requested proof from completed proof.

Preserve the recording and supplied instructions. Keep raw analysis intact and review speech timing honestly. Record uncertain names, claims, estimated regions, and listening limitations. Request permission before changing supplied narration, audio, or visual instructions. Internal design and sample reviews proceed autonomously.

Keep output at 1080×1920 with top captions and the approved language shaping. Use the shared stage and timing helpers. Prefer specific subjects, essential body type, meaningful changes, and purposeful holds. Every scene need not be a technical mechanism, card, or diagram. Follow the scene-craft contract for subject sourcing, layer control, event wiring, and rendered review.

For production, run `video:check-production` before rendering, inspect actual samples, and repair weak sequences. After the full render, use `video:review-evidence`, inspect phone-size frames and motion, complete `creative-review.json` truthfully, and run `video:check-creative` before export. Complete media, motion, and 9:16 verification per workflow.md. Technical pass flags do not establish creative quality.

Give review feedback as actual time/frame and object, viewer impact, cause, repair, and new evidence required. Maintain `work/current/progress.md`. Report only work and checks actually performed, with incomplete listening/playback or production stages explicit.
